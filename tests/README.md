# ローカル検証

このディレクトリの検証は、実ユーザーのアカウントや外部サイトへ投稿せずに行います。

`ui-smoke.cjs` はChromiumとPlaywrightを使い、本棚・原稿編集・生成イベント受信・候補採用・読書・バックアップの操作を検証します。NativeBridgeをテスト用に置き換えます。これはAndroid実機でのログイン・実推論・サイトへの実投稿の成功を意味しません。

実行環境にPlaywrightとChromiumを用意して実行します。

```sh
CHROME_BIN=/path/to/chrome-headless-shell node tests/ui-smoke.cjs
```

スクリーンショットと検証結果は、環境変数 `NOVELSTUDIO_QA_DIR` で指定した作業ディレクトリへ保存します。未指定の場合はOSの一時ディレクトリを使います。


## 1.1.0 の追加検証

1.1.0時点のUI検証は22シナリオでした。

タイトル候補（5・10・20候補の依頼、編集・コピー・選択採用）、あらすじ候補（採用・取消・中断復元）、生成中の作品切替でも出力先が変わらないことを検証します。局所的なファイルエラーの通知が文章生成を中止しないことも確認します。

挿絵は、ChatGPT画面への指示引継ぎ、設定後の1タップのAPI要求、画像の取込・取消・参照検証・書出要求・話への保存・読書画面表示・再起動後の復元を検証します。画像処理中のバックアップ復元・対象話の削除はブロックします。画像にはローカルの1ピクセルPNG、API・SAFにはNativeBridgeのテスト用実装を使います。このテストは画像APIの実課金・実生成やAndroidの画像デコード・ZIPバイト処理の検証ではありません。画像・ZIPの実処理は native 側の別検証が対象です。

バックアップ操作のUI検証では、原稿JSONと画像参照をnativeのZIP出力入口に渡すこと、ログイン情報やAPIキーを含めないことを確認します。360px・768px幅で全主要画面の横はみ出しも検証します。日本語フォントが入っていない実行環境ではスクリーンショットの日本語表示が代替字形になります。APKはAndroid端末のフォントを使い、外部フォントを読み込みません。


## 1.2.0 の追加検証

現行のUI検証は **30シナリオ** です。結果は `ui-results.json` に記録しています。

NativeBridgeの保存済み進捗を模した独立セッションで、次の操作を追加検証しています。

- UIを作り直したときの本文・作品情報・画像の進捗復元。アクティブな処理を中断扱いにせず、API要求を自動で再送信しないこと。
- 全文snapshotの置換、受信済みseq以下の重複delta除外、seqが欠けた場合の同期。別作品の編集中の本文・入力欄の内容とフォーカスを保持すること。
- native側で反映済みの同seq terminalを、UIの保存に成功してからACKすること。原稿保存失敗時はACKせず、native ACK失敗時は次の保存で再試行すること。
- 採用・破棄後に古いterminalが再配送されても候補を復活させないこと。画像も重複追加しないこと。
- 中断結果と開始時原稿を確認できない結果を復元し、採用時に確認すること。別候補との衝突・画像50枚上限では結果をACKしないこと。
- 通知・電池設定の明示的な操作、通知が無効でも生成操作を開始できること、局所的なnoticeが進行中の生成を中止しないこと。

UI検証はテスト用のnative実装を使います。Android実機の省電力制御、画面消灯中のネットワーク継続、実アカウントでの生成成功を確認するテストではありません。Foreground Serviceと保存処理はnative側の別検証が対象です。

## 1.3.0 の追加検証

- `bash tests/batch/run.sh /path/to/org-json.jar`：製品版Runtime・Journal・BatchGeneration・DraftStoreを組み合わせ、Android/通信だけを代替。UIが存在しない100話連続処理、部分再開、プロセス再作成、保存境界、サービス時間制限、遅延イベント、保存障害、次キューを検証します。
- `tests/ui-smoke.cjs`：途中再開の指示保持、100話の作成、タブ切り替え、進捗復元、ストリームの再同期・重複防止、編集保護を検証します。実APIへのアクセスは行いません。
- 実機のDoze・省電力・通知や長時間連続稼働は、この環境では実施していません。
